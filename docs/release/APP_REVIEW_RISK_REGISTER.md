# Men's Discipline App — App Review & Launch Risk Register

**Last updated:** 2026-08-20

**Purpose:** Make review/compliance risks explicit early instead of discovering them at submission. This register tracks risk; it does not redefine locked MVP behavior.

| ID | Risk | Severity | When to resolve | Mitigation / evidence |
|---|---|---:|---|---|
| R-01 | Family Controls Distribution entitlement or provisioning is unavailable for the main app or a required extension | P0 | Phase 03–08 | Apple has assigned Family Controls (Distribution) to both the main app and `com.temperline.mensdiscipline.deviceactivitymonitor`. Signed development profiles for both targets contain Family Controls and the shared App Group, and the Release configuration device build passed with development provisioning. Distribution archive/profile inspection and actual TestFlight operation remain required. |
| R-02 | Guideline 4.10 explicitly names Screen Time APIs; Apple provides no explicit safe harbor for this product's monetization structure | P1 | Monetization + submission | Camera is no longer in the MVP release package, reducing this risk to Screen Time packaging. Existing approved paid apps suggest Screen Time can be integrated into paid products in practice, but approval is not guaranteed. Do not change the locked subscription model solely because of 4.10. Review final paywall, metadata, value proposition, and Review Notes. |
| R-03 | Screen Time scheduling/DeviceActivity behavior unreliable on target iOS versions | P0 | Phase 03 + beta | On Clover (iPhone 13, iOS 26.6), Incomplete and Completed callbacks passed with the host inactive and again after force-quit; Incomplete also passed after force-quit plus reboot. Evidence includes `intervalDidStart / appliedShield`, `skippedCompletedToday`, Apple's `Restricted` UI, retained selection/accountability, replacement and Cancel recovery. Continue timezone/DST, midnight and multi-version beta tests. Apple documents that callbacks may wait until the device is used within the interval, so messaging must not promise wall-clock precision. |
| R-04 | App positioned as sexual gratification / explicit sexual content rather than wellness/performance | P0 | Brand, UI, Store listing | Preserve non-explicit performance/wellness positioning; conservative visuals/copy/age rating. |
| R-05 | Unsupported medical/sexual-performance claims trigger heightened review | P0 | Copy + launch | No ED treatment, testosterone, guaranteed erection/sexual-performance claims; document methodology for any measurement claims. |
| R-06 | Subscription lacks ongoing value or reviewer cannot understand value | P0 | Phase 13 | Explain ongoing proprietary training/accountability value; keep IAP model obvious in metadata/review notes. |
| R-07 | Paywall pricing/trial disclosure rejected | P0 | Phase 13–15 | Full billed price most prominent; explicit 3-day trial and post-trial price; renewal/cancel wording; Terms + Privacy + Restore. |
| R-08 | Sandbox/TestFlight purchase fails for reviewer | P0 | Phase 15 | Production-like TestFlight test; product metadata complete; RevenueCat mappings; restore/expired/cancelled paths tested. |
| R-09 | Forced login with insufficient account-based value | P1 | UX architecture | Preserve no-login first routine; only require account for genuine account features. |
| R-10 | Account creation exists but in-app deletion/token revocation missing | P0 | Account implementation | In-app delete; server deletion; Sign in with Apple revocation where applicable. |
| R-11 | App Privacy labels mismatch SDK behavior | P0 | Phase 14–15 | Maintain data map + SDK inventory; re-audit every SDK release. |
| R-12 | Invalid/missing Privacy Manifest or Required Reason API declaration | P0 | Every release | `PrivacyInfo.xcprivacy`; Xcode privacy report; third-party SDK manifest/signature audit. |
| R-13 | Reviewer cannot reproduce the Family Controls accountability flow | P0 | Submission | Exact Review Notes, demo account, clear app-selection/schedule/guided-routine/unlock steps, and demo video if needed. Camera setup is not part of the MVP reviewer path. |
| R-14 | App accidentally ships iPad support without real iPad UX/screenshots | P1 | Build config | Make iPhone-only decision explicit; configure target accordingly, or fully support iPad. |
| R-15 | Broken Privacy/Terms/Support links | P0 | Submission | Automated/manual preflight check; monitored support mailbox. |
| R-16 | Age rating inconsistent with mature/suggestive/wellness content | P1 | App Store metadata | Complete questionnaire conservatively based on real content; no explicit imagery. |
| R-17 | Export-compliance questionnaire/doc missing | P1 | First TestFlight/App Store build | Determine encryption use; configure Info.plist / App Store Connect correctly. |
| R-18 | EU DSA trader details block EU distribution or expose unexpected contact details | P1 | Before EU storefront | Decide territories early; verify business contact details before enabling EU. |
| R-19 | First-launch Individual seller identity is not reflected consistently in account, support, legal or marketing materials | P1 | Before App Store submission | DEC-022 accepts the current Individual membership for first launch; verify all first-launch materials against the actual seller identity. Organization conversion is deferred, not a launch blocker. |
| R-20 | Small Business Program not effective at launch | P1 | Before launch | Apply through the current account after the Paid Apps Agreement, with lead time; verify status before real paid sales. |
| R-21 | Third-party asset/license issue (music/fonts/icons/AI/UGC) | P1 | Asset finalization | Maintain license ledger and commercial-use evidence; company owns/has license to submitted assets. |
| R-22 | Secrets/API keys committed to Git | P0 | Development | `.gitignore`, environment/secret management, rotate exposed credentials immediately, least-privilege keys. |
| R-23 | Lock schedule breaks around midnight, timezone, DST, app termination or reboot | P0 | Phase 03–15 | The native daily interval and App Group date-scoped state remain the baseline. On Clover, force-quit Incomplete applied the shield, force-quit Completed skipped it, and force-quit plus reboot Incomplete applied it; state and callback evidence persisted. Keep midnight rollover, timezone/DST and multi-iOS coverage as explicit later system-edge tests before production reliability is claimed. |
| R-24 | Subscription/account state diverges across reinstall/device/account | P1 | Phase 13–15 | RevenueCat entitlement source of truth + restore path + identity mapping strategy. |
| R-25 | Strict framing or pose false negatives prevent an honest user from completing the routine or unlocking selected apps | Closed (MVP) | Phase 03.9 | Real-device Kneeling Drive use confirmed the risk: partial-body/frontal framing and daily calibration were too brittle. DEC-021 removes Camera/Vision from the MVP completion path rather than adding a counting workaround. Historical implementation remains in Git for post-MVP R&D. |
| R-26 | Family Controls authorization status initializes as `notDetermined` after cold launch before the persisted authorization is published | P0 | Phase 03 before app selection/lock state relies on authorization | The app observes the publisher, displays `checking`, reads after App active and uses bounded retries. Five approved-state cold starts passed. Phase 03.11 adds denied-only safety reconciliation: revoke resolved to denied, cancelled schedules and removed shields while preserving selection; denied re-request remained unavailable; re-approval recovered approved/data-access state and selection. Transient `notDetermined` does not trigger destructive cleanup. |
| R-27 | A stale, corrupt, or mismatched opaque FamilyActivitySelection leaves the diagnostic shield inconsistent or difficult to remove | P0 | Phase 03 selection/shield proof | Persist Apple's Codable selection without exposing token contents; Phase 03.8 read the migrated selection from verified App Group storage and the monitor callback applied exactly its one category token. Instagram remained usable while selected-category YouTube was restricted, Reset restored access, and final Cancel left all diagnostic shield counts at zero. Absent/empty/corrupt/unavailable state never constructs a broad policy. Corrupt scheduled state remains untested on-device. |
| R-28 | A production/TestFlight build fails to load its bundled JavaScript independently of Metro | P0 | Before TestFlight acceptance | A clean signed Release configuration build embedded `main.jsbundle`, installed on Clover and cold-launched directly while Metro was fully stopped; `No script URL provided` did not appear. This used development provisioning, so distribution archive/profile inspection and an actual TestFlight cold launch remain required before this release risk is closed. |
| R-29 | Live pose latency, orientation, partial-body loss, or depth ambiguity causes inaccurate counts across realistic angles | Closed (MVP) | Phase 03.9 | Technical counting capability was demonstrated, but mandatory UX feasibility was rejected: landscape side was materially better than portrait and front/near-front plus partial framing were unreliable. The current MVP source removes the live route, camera purpose string, and capture runtime; no seven-movement Camera rollout is planned. |
| R-30 | Guided training completion or interruption recovery diverges from accountability state and leaves selected apps incorrectly locked/unlocked | P0 | Phase 03.10 + beta | The data-driven five-set/four-rest engine, duplicate-safe completion, foreground interruption reset, guided completion → shared state → unlock, and later same-day schedule suppression passed. Phase 03.11 force-quit tests preserved correct Incomplete/Completed accountability and shield outcomes. Date-boundary and final production session-recovery UX remain before release. |

## Exit rule
No public App Store submission while any P0 risk is unresolved or lacks a documented mitigation/test result.
